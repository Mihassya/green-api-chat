# GREEN-API Chat

Веб-чат для отправки и получения текстовых сообщений через [GREEN-API](https://green-api.com/max). Тестовое задание.

**Демо:** https://green-api-chat-liart.vercel.app

Стек: React 18, TypeScript, Tailwind CSS, Vite.

## Что умеет

- вход по данным инстанса GREEN-API (`idInstance`, `apiTokenInstance`, `apiUrl`) с проверкой, что инстанс авторизован;
- создание чата по номеру телефона;
- отправка текстовых сообщений и получение ответов;
- светлая и тёмная тема, адаптивная вёрстка для телефона.

Интерфейс сделан по мотивам [web.max.ru](https://web.max.ru/), фон переписки — в стиле WhatsApp.

## Как проверить

Для входа нужен свой инстанс GREEN-API, на бесплатном тарифе «Разработчик» это занимает пару минут:

1. Зарегистрируйтесь в [личном кабинете](https://console.green-api.com) и создайте инстанс.
2. Авторизуйте его: отсканируйте QR-код в приложении мессенджера на телефоне.
3. В настройках инстанса включите **получение входящих уведомлений** и оставьте **URL для уведомлений пустым** — приложение забирает сообщения само, без вебхука.
4. Откройте [демо](https://green-api-chat-liart.vercel.app), введите `idInstance`, `apiTokenInstance` и `apiUrl` из карточки инстанса.
5. Нажмите «+», введите номер получателя (например `79991234567`) и отправьте сообщение.
6. Ответьте на него с телефона получателя — ответ появится в чате.

## Как это работает

- **Отправка** — метод [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/), получатель задаётся как `<номер>@c.us`.
- **Получение** — [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/): приложение в цикле вызывает `ReceiveNotification`, обрабатывает входящее и подтверждает его через `DeleteNotification`. Подтверждаются все уведомления, даже не текстовые, иначе очередь встанет.
- **Вход** — перед входом вызывается `getStateInstance`, чтобы сразу сказать, если токен неверный или инстанс не авторизован.
- Чаты, сообщения и данные входа хранятся в `localStorage` браузера.

### Нюансы, на которые наткнулся

- **Вебхук не подходит без бэкенда**, поэтому выбран HTTP API (как и требует задание).
- **В MAX входящее приходит с внутренним id пользователя**, а не с номером, по которому создан чат. Чтобы ответ не уехал в новый чат, сообщение привязывается к существующему чату по полю `senderPhoneNumber`.
- **`receiveTimeout` срабатывает не всегда**: на пустую очередь сервер иногда отвечает сразу. Чтобы не слать запросы непрерывно, после пустого ответа делается пауза в секунду.
- **Опрашивать очередь должна одна вкладка.** Если открыть чат в двух вкладках, они будут забирать входящие друг у друга.

### Про мессенджер

API у GREEN-API одинаковый для MAX, Telegram и WhatsApp, поэтому код от мессенджера не зависит — выбор при входе влияет только на подписи. Проверял на инстансе WhatsApp: создать инстанс MAX в кабинете не получилось, а сервер Telegram-инстанса не отвечал.

## Запуск локально

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:5173. Сборка — `npm run build`.

## Структура

```
src/
  api/greenApi.ts        запросы к GREEN-API
  hooks/usePolling.ts    получение входящих сообщений
  hooks/useTheme.ts      светлая/тёмная тема
  store/chatStore.tsx    состояние: чаты, сообщения, данные входа
  components/            экраны и элементы интерфейса
```
